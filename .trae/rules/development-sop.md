# 开发操作规范 · Development SOP

> 适用于所有插件的日常开发流程。AI 必须在每次代码变更中遵守本规范。

---

## 阶段一：边开发边反思（Develop with Reflection）

每写一个函数/类/模块，**必须**在回复中附上以下反思：

| 检查项 | 自问 | 不通过则 |
|--------|------|---------|
| 单一职责 | 这个函数/类只做一件事吗？ | 拆分 |
| 依赖方向 | 依赖了不该依赖的模块吗？（插件之间不能互相依赖） | 重构 |
| 命名准确 | 变量/函数名 3 秒内能看懂吗？ | 重命名 |
| 空安全 | 每个可空参数都处理了 null 吗？ | 补判空 |
| 异常处理 | 网络/文件/数据库操作有 try-catch 吗？ | 补异常处理 |
| 复用性 | 这段逻辑在其他地方会用到吗？→ 抽到 shared 或 utils | 提取 |

**输出格式**：每段代码后附一行 `<!-- 反思: [检查项] → [结论] -->`，不通过的立即当场改。

## 阶段二：自检自查（Self Review）

写完一个完整功能模块后，按以下顺序自查：

### 2.1 静态分析

```bash
cd platform/plugins/<插件名> && dart analyze
```

必须 **0 error, 0 warning**。有 warning 不能进入下一步。

### 2.2 单元测试

```bash
cd platform/plugins/<插件名> && dart test
```

- 每个新增的 public 函数/方法必须有至少 1 个测试
- 修改的现有函数必须更新对应测试
- 覆盖率不要求 100%，但核心逻辑路径必须覆盖

### 2.3 Widget 测试

```bash
cd platform/plugins/<插件名> && flutter test
```

- 每个新增页面/对话框必须有至少 1 个 widget 测试
- 测试包含：渲染验证、交互验证（点击/输入）、边界状态（空数据/加载中/错误）

### 2.4 代码优化

自查清单：

| 检查项 | 操作 |
|--------|------|
| 有重复代码块（≥3 行）？ | 提取为私有函数 |
| 有魔法数字/字符串？ | 提取为命名常量 |
| 嵌套层级 > 4？ | 提取子 Widget |
| build 方法 > 50 行？ | 拆分 |
| import 未使用？ | 删除 |
| 注释是否必要？（代码自解释则不需要） | 删除冗余注释 |

## 阶段三：功能验收（Acceptance Check）

对照需求文档中的 Gherkin 验收标准，逐条验证：

### 3.1 功能完整性

| 检查项 | 验证方式 |
|--------|---------|
| 主流程（Happy Path） | 手动跑一遍，确认无报错 |
| 异常流程（Error Path） | 逐个触发异常场景，确认提示文案正确 |
| 边界条件（Edge Case） | 空输入、超长输入、并发操作 |

### 3.2 用户体验

| 检查项 | 标准 |
|--------|------|
| 操作反馈 | 每次点击有视觉反馈（按钮缩放/loading/成功提示） |
| 加载状态 | 网络请求有 shimmer/skeleton 或 CircularProgressIndicator |
| 空状态 | 列表为空时显示插画 + 引导文案，不显示空白页 |
| 错误状态 | 网络错误不显示技术堆栈，显示用户可理解的中文提示 |
| 键盘体验 | 输入框支持 Enter 提交、Escape 关闭 |
| 手势习惯 | 左滑删除、长按菜单、双击放大（遵循平台惯例） |
| 响应式 | 手机竖屏/横屏/平板/桌面四种尺寸均不溢出 |

### 3.3 性能

| 检查项 | 标准 |
|--------|------|
| 页面首次渲染 | ≤ 300ms（dev 模式，真机） |
| 列表滚动 | 60fps 无卡顿（使用 ListView.builder，不用 ListView） |
| 内存 | 页面退出后 dispose 所有 controller |

## 阶段四：热部署与运行测试（Hot Reload & Run）

### 4.1 热部署验证

AI 无法向已运行的交互式终端发送按键，按以下流程操作：

**AI 侧（自动执行）**：
1. 修改代码完成后，执行 `dart analyze` 确认 0 error
2. 输出验证清单，提示用户按 `R`：

```
✅ dart analyze 通过，0 error 0 warning。

请在 flutter run 终端按 R（热重启），验证以下：
- [ ] 修改的 UI 即时生效
- [ ] 状态管理（Riverpod）的 state 保持正确
- [ ] 无 "Hot reload was rejected" 错误
```

**用户侧**：在 flutter run 终端按 `R`，对照清单逐项确认。

**如果热重载被拒绝**（state 变更导致无法热重载）：
- AI 执行 `kill` 旧进程 → `flutter run` 重新启动（全量编译）
- 这比找热重载问题更快，通常 10-30 秒完成

### 4.2 完整运行测试

```bash
cd platform/plugins/<插件名> && flutter run
```

独立运行模式测试：

- 插件独立 App 正常启动
- mock 认证正常
- 离线功能正常（无后端时降级）

### 4.3 后端测试

```bash
cd platform/server && uvicorn main:app --reload
```

- 新增 API 端点返回正确状态码
- 异常情况返回正确的错误码和提示
- 数据库表自动创建

## 违规处理

| 违规 | 处理 |
|------|------|
| `dart analyze` 有 error | 不准提交，当场修 |
| 新增功能无测试 | 不准进入下一功能，补测试 |
| Gherkin 场景未验证 | 标记为 `[TODO: verify]`，上线前必须验证 |
| 热重载被拒绝 | 不准继续开发，先修 hot reload 问题 |

---

## AI 行为约束

1. 写完代码后**必须**主动执行 `dart analyze`，不等待用户要求
2. 写完代码后**必须**提示用户执行热重载验证，并给出验证清单
3. 发现代码异味**必须**当场指出并修复，不允许"先这样后面再改"
4. 每完成一个功能模块，**必须**输出阶段二的检查结果表格
